Find a variable

Search every column in every register documented in this guide

Published

September 5, 2026

Overview of registers answers “what is in this register?”. This page answers the opposite: “which register has this variable, and what does it look like there?”

Search by column name, by what it means, or by register. Everything comes from the same schema as the register tables, so the two pages cannot disagree.

This is a starting point, not an authority. The names, types and value sets here are collected from DST’s and Sundhedsdatastyrelsen’s published documentation, and they can be out of date or simply wrong. Codes change meaning, columns are retired, and what is documented is the register, not what your project ordered.

Check two things before you rely on anything you find here. The current format tables on the DST server, which are the authoritative code lists and are updated without this page knowing, and your own delivered dataset with colnames() and a look at the actual values. A column can be missing from your extract, spelled differently, or arrive as a type that changes what your code does.

Found something wrong? Open an issue or use the feedback box below. A mistake spotted once is a morning nobody else loses.

NoteWhat a result shows you

Type is the R type you get after loading. Where it says unverified, no published source gives a type for that column, so the one shown is our own assumption: DST publishes data types for none of its registers, and only Sundhedsdatastyrelsen does, for the health registers. Confirm with sapply(class) before relying on it, especially for code columns, which lose their leading zeros if they arrive as numbers.

Years is what DST or Sundhedsdatastyrelsen documents that they hold, not what your project was delivered. It is shown only when a column covers a different period from its register, which is the case worth noticing: a column that stops in 2003 is a silent hole in a series that runs to 2024.

Same name, several registers is the reason this page exists. koen in BEF is a number, c_sex in LPR2 changed coding in 2005, borger_koen in LPR3 is text with an unknown value set. Three answers to one question, and the register pages show them one at a time.

The value set is folded under each coded column: what U means in civst, what 3 meant in c_pattype before 2014. Working that out is normally the slow part, and where the codes are too many to list, the fold-out links to the classification instead.

Under the register name you get how to join it, what period it covers, and a warning if it is closed. A column in dodsaars is fine for causes of death and wrong for censoring, and the search says so before you use it.

Replaced by marks a column with a successor, like van_vtil. Using it alone leaves a silent hole in the middle of a series.
